# v0.5.2 provider-routing hotfix

After installing v0.5.1 on the affected 8 GB Apple Silicon Mac, two remaining routing defects were
reproduced from the released package:

- the Ollama connection test chose the alphabetically first capability (`llama3.1:8b`) instead of
  the configured default (`llama3.2:1b`);
- saving an explicitly selected NVIDIA NIM profile was blocked by the local-only initialization
  default, despite the user requesting a real remote connection test.

The connection probe now prefers a provider's configured default and then its configured role
models. Saving and testing a remote profile is treated as an explicit request to persist `mixed`
privacy mode, and the response reports that policy transition. Re-importing an existing profile
now stops before credential mutation and requires a second explicit confirmation to replace it.

## Real-provider evidence

- NVIDIA NIM `z-ai/glm-5.2`: HTTP 200, bounded generation verified, first token observed.
- Ollama `llama3.2:1b`: native generation probe selected from the configured default, first token
  observed in 2.4 seconds, and `/api/ps` was empty after the request.
- Provider secrets remained in the macOS login keychain and did not enter the configuration file
  or test output.
